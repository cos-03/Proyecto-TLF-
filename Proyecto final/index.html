01 · El lenguaje

Una receta para cada lote

El programa expresa lecturas, decisiones, ciclos y acciones de dominio sin ejecutar equipos físicos.

¿Qué puede describir?

Declaraciones var, asignaciones, condicionales si / sino, ciclos mientras y las acciones regar, mostrar y alerta. Las expresiones incluyen paréntesis, menos unario y operadores aritméticos con precedencia.

riego_valido.agro 
programa lote_3 {
    var humedad = 42;
    var meta = 60.5;

    si (humedad < meta) {
        regar((meta - humedad) * 2);
    } sino {
        alerta("humedad óptima");
    }
}

Cuatro pasos de entrada a árbol

4ResultadoÁrbol de derivación o lista de errores.
03 · Formalismo léxico

El AFD reconoce los tokens

Las palabras reservadas comparten el estado de identificador; luego se clasifican con una tabla.

Definición formal

M = (Q, Σ, δ, q0, F). El sumidero absorbe entradas inválidas y cada token conserva su recorrido de estados.

Estadosq0…q25 y qE
AceptaciónF = Q \ {q0, q3, q5, q13, qE}
CoincidenciaSe conserva el último prefijo aceptado
ReservadasSe clasifican después de reconocer ID

Recorrido ilustrativo

El AFD distingue enteros, decimales y estados de rechazo intermedios.

q0→ q2→ q2→ q3→ q4

04 · Estructura sintáctica

De una G0 ambigua a G2 LL(1)

La precedencia se fija por niveles y la recursividad izquierda se transforma en colas recursivas por la derecha.

Precedencia de expresiones

unario −→ × ÷→ + −

En G0, ID - ID * ID admite más de un árbol porque la regla no fija qué operador queda en la raíz. G2 separa expr, termino y factor.

Ver la ambigüedad de G0 
<expr> ⇒ <expr> - <expr>
      ⇒ ID - <expr> * <expr>
      ⇒ ID - ID * ID

<expr> ⇒ <expr> * <expr>
      ⇒ <expr> - <expr> * <expr>
      ⇒ ID - ID * ID

Producciones clave de G2

<expr>        ::= <termino> <expr'>
<expr'>       ::= MAS <termino> <expr'>
                | MENOS <termino> <expr'> | ε
<termino>    ::= <factor> <termino'>
<termino'>   ::= POR <factor> <termino'>
                | DIV <factor> <termino'> | ε
<factor>      ::= MENOS <factor>
                | PAR_A <expr> PAR_C | ID | NUM

Los conjuntos FIRST/FOLLOW y la especificación extendida están en la documentación formal.

05 · Casos de prueba

Válido o con errores

Los ejemplos muestran la salida del analizador; este visor web es informativo y no ejecuta el parser de Python.

programa demo {
    mostrar(-humedad + meta / 2);
}
Resultado esperado: programa correcto y árbol de derivación. La división se agrupa dentro de un término antes de la suma.
var humedad = 45 @ 2;
var umbral = 12.;
si (humedad ! 30) { ... }
El AFD reporta @ y . desde q0, y ! aislado desde q13. También puede detectar cadenas sin cerrar desde q5.
programa demo {
    var humedad = 50
    si humedad < 60) { regar(5); }
}
El parser reporta el punto y coma faltante y el paréntesis requerido, con línea y columna. La recuperación permite continuar con sentencias posteriores.
06 · Configurador

Ingresa valores, no código

Completa los datos de riego. AgroScript construye el programa y señala qué regla debe cumplir cada valor.

Cada campo recibe un solo NUM: dígitos, con punto decimal opcional. No escribas operadores ni instrucciones.

Resultado

El programa se arma automáticamente con una estructura permitida por la gramática. Puedes revisar el código generado, pero no necesitas escribirlo.

08 · Ejecución local

Prueba el analizador Python

El árbol del programa generado se muestra arriba. Para analizar otro archivo o regenerar el resultado, ejecuta el parser desde Proyecto final.

python main.py ejemplos/riego_valido.agro
python main.py ejemplos/riego_valido.agro --tokens
python -m unittest discover -s tests -v
